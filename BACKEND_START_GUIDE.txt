ERP-Pos Backend — Full Start Guide (from Frontend analysis)
============================================================
Source: Frontend nav.js, pageConfigs.js, settingsPanel.js, reports.js,
        ListPage actions, ModulePage specials, api.js
Backend root: Backend/
Frontend root: Frontend/

Status tags:
  [DONE]     = already wired API exists
  [PARTIAL]  = tables and/or read API exist; writes/actions still missing
  [TODO]     = not built yet (Frontend is mock/seed UI)

Build order (do not skip ahead into Sales/POS/Payroll first):
  foundation → ACL → master data → settings masters → accounting write
  → inventory → sales → purchase → POS → manufacturing → HRM → support → reports

Daily pattern (every resource):
  1. Migration → Model → Seeder
  2. Form Request (validation)
  3. Controller + routes (auth:sanctum + company_id scope)
  4. Postman / Thunder Client test
  5. Frontend api.js client + list/form/details wire

Shared list API contract (assume for every list resource unless noted):
  GET    collection   paginated + filters + search + sort
  POST   collection   create
  GET    /{id}        details
  PUT/PATCH /{id}     update
  DELETE /{id}        delete
  PATCH  status       Active/Inactive, Approve, Cancel, Close, Draft, etc.
  Extra actions listed per module below

START HERE (fixed recommendation)
==============================================================================
1. Finish Phase 0 + Phase 1 (company scope + response format)
2. Build Phase 2 ACL next (Role/User UI already on localhost)
3. Then Phase 3 master data + Phase 4 settings masters
4. Only then Accounting writes → Inventory → Sales/Purchase → POS → rest

Avoid starting first: Sales, POS, Payroll/Manufacturing deep flows —
without ACL + master data + settings they become fragile.
